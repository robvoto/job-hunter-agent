Advanced Matching Rules

Engine-tuning controls kept separate from the main candidate profile editor.

Capability Matrix

Each row is one capability the engine can score against job descriptions. Give it a clear label, choose your actual strength, choose how central it is to your target roles, and list the job-ad words that prove the capability is present.

How to classify a capability

Core skill means this is one of your main strengths for the roles you want.

Useful support means it is a real skill, but it should support matching rather than define it.

Background only means it is acceptable context, but it should not pull roles up by itself.

Not for me means jobs that lean on this capability are probably the wrong direction.

Job ad keywords are the short phrases the app scans for in job descriptions to detect that capability. Use JD wording like stakeholder management, workshops, kanban, vendor management.

Keywords stay tucked into each row so long matrices remain scannable.

Requirement Exclusions

How mandatory blockers work

Add skills or tools you do not have (e.g., SAP, NV1 clearance). The engine reads the context around the word. If it's a hard requirement ("Must have SAP"), the job is rejected. If it's just desirable ("SAP is a plus"), the job is kept but flagged as a risk.

Advanced hard-blockers (Exact phrase & Regex)

Unlike the mandatory blockers above, these are hard blocks. If a job description contains these exact phrases or patterns anywhere in the text, the job is immediately rejected.

Exact phrases to completely ban. E.g., adding payroll rejects any job mentioning the word "payroll".
Regular expressions for complex pattern blocking (e.g., catching variations of a certification).
